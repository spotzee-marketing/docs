## Send a test message

<Steps>
  <Step title="Enter the server settings">
    Provide the hostname or IP, port, username and password supplied by your SMTP provider. Choose the required security mode: None, STARTTLS or SSL. The API values are `none`, `tls` and `ssl`.
  </Step>
  <Step title="Set sender and recipient">
    Use a sender permitted by the account and a recipient you control. The test submits a real message, so avoid customer addresses or sensitive content.
  </Step>
  <Step title="Review the response">
    Inspect the reported result and diagnostics. Authentication, connection, encryption and sender restrictions can each prevent submission. Follow the provider's configuration instructions before retrying.
  </Step>
  <Step title="Confirm arrival">
    Check the recipient's inbox and spam folder. Successful submission alone does not prove delivery or inbox placement.
  </Step>
</Steps>

## Protect the test credentials

The test service receives the credentials and uses them to authenticate with the SMTP server. **None** does not encrypt that SMTP connection. Use a dedicated test account or app password where supported, and choose encrypted transport according to your provider's instructions.

Provider authentication policies vary. This form accepts a username and password; do not assume every account supports password-based SMTP or that an app password bypasses a disabled authentication method.

For a connection-only check, use the [TCP port checker](/guides/tools/blacklist-security/tcp-verifier). To inspect a received message, use the [email spam checker](/guides/tools/email-validation/email-spam-checker).
