Use the TCP port checker to test whether a host and port accept a connection from the test service. It opens a connection and sends a line break. It does not verify SMTP, TLS or any other application protocol.

<Info>
Open the [TCP port checker](https://spotzee.com/tools/tcp-verifier/). Extended API calls use your Spotzee credit balance; see [pricing](https://spotzee.com/pricing/) for current rates.
</Info>

## Check a connection

<Steps>
  <Step title="Choose the destination">
    Use the hostname or public IP address and port supplied by the service owner. For API access, send `domain_ip` and `port` as form fields to `POST /generic/dns/tcp-verifier`.
  </Step>
  <Step title="Read the result">
    The response contains `data.connection`: `success` when the connection and write complete, or `fail` when they do not. A failed connection can still return HTTP `200`, so inspect the result field.
  </Step>
  <Step title="Investigate a failure">
    Check the host, port, DNS and firewall configuration. The result does not distinguish a refused connection, a timeout or a failed write. Test from your own sending environment too, because its network access can differ.
  </Step>
</Steps>

For SMTP submission, use the port and encryption mode required by your provider. A successful TCP result does not confirm credentials or message acceptance. Use the [SMTP email test](/guides/tools/smtp-testing/smtp-email-test) for that next check.
