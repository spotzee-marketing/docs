Use an IP blacklist check to inspect the configured DNS blacklists for a sending address. A listing can help explain a delivery rejection, but recipients use different filtering rules.

<Info>
Open the [IP blacklist check](https://spotzee.com/tools/ip-blacklist-check). Extended API calls use your Spotzee credit balance; see [pricing](https://spotzee.com/pricing/) for current rates.
</Info>

## Check a sending IP

<Steps>
  <Step title="Enter one address">
    Supply either `ipv4` or `ipv6`, not both. Use the public sending address from your provider or mail headers. Private or reserved addresses can be rejected.
  </Step>
  <Step title="Choose the scan">
    Use `popular` for the smaller configured set or `full` for the full set. The API defaults to `full`. IPv6 checks use only lists marked as supporting IPv6, so they do not query every IPv4 list.
  </Step>
  <Step title="Review each list">
    Inspect `data.check_results` and the `listed`, `unlisted` and `errors` totals in `data.results`. Individual statuses are `Listed`, `Unlisted` and `Error`.
  </Step>
  <Step title="Confirm the result">
    Visit the named list operator's lookup and follow its current explanation and removal policy. Resolve the cause before requesting removal.
  </Step>
</Steps>

## Understand the limits

A query failure can produce `Error`. Other DNS responses that the tool does not recognise as a listing can produce `Unlisted`. The IP check treats returned addresses beginning with `127.` as listings, which can include a list operator's query-error response. Confirm a reported listing with that operator before changing your sending configuration.

A clear result does not guarantee inbox placement. Check the [sending domain](/guides/tools/blacklist-security/domain-blacklist-check) and [SenderScore](/guides/tools/dns-auth/senderscore-lookup) when investigating reputation, and use the recipient's delivery diagnostic to identify the actual rejection.
