The optional `x-spotzee-client-type` header identifies your client. The Main API uses `mcp` when applying the MCP rate-limit multiplier where per-key enforcement is available. The header does not bypass authentication, credit limits or per-IP limits.

```http
x-spotzee-client-type: mcp
```

Check [Rate limits](/guides/api-rate-limits) before relying on extra request capacity. Omitting the header or sending an unrecognised value does not receive the MCP multiplier.

## Recognised values

Use the value that describes your integration:

| Value | Use for |
|---|---|
| `mcp` | MCP servers and agent runtimes that fan out parallel tool calls |
| `mobile` | Native iOS or Android apps using the official mobile SDKs |
| `sdk-js` | JavaScript SDK integrations (set explicitly on the generated client) |
| `sdk-android` | The official Android SDK (set automatically) |
| `sdk-ios` | The official iOS SDK (set automatically) |
| `cli` | Command-line tools (deploy scripts, one-off backfills, your own CLI) |
| `unknown` | Unspecified client; no MCP multiplier. |

## When to set it

<Tabs>
  <Tab title="MCP server">
    Set `x-spotzee-client-type: mcp` for MCP requests. Keep concurrency bounded and honour rate-limit responses.
  </Tab>
  <Tab title="CLI tool">
    Set `x-spotzee-client-type: cli` to identify command-line requests.
  </Tab>
  <Tab title="Custom integration (your own backend)">
    Leave the header off. Your traffic is treated as `unknown` and gets the standard rate-limit policy for your account. Use `mcp` only for MCP integrations.
  </Tab>
  <Tab title="Official SDK">
    The Android and iOS SDKs set their own values. For the generated JavaScript client, set `x-spotzee-client-type: sdk-js` in the client configuration.
  </Tab>
</Tabs>
